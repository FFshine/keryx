# Keryx — Hermes Agent Mobile Client

Keryx (Greek: κῆρυξ — "herald, messenger") is a **Flutter** mobile client for [Hermes Agent](https://hermes-agent.nousresearch.com). It connects to a Hermes Gateway server via its OpenAI-compatible API, providing a native chat experience on Android with multi-session management, streaming responses, image attachment, and Runs API support.

## Quick Start

### Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Flutter | 3.41+ | `flutter --version` |
| Android SDK | 35 (API 35) | via `sdkmanager` or Android Studio |
| AVD | arm64-v8a | Android 35 emulator image |
| Hermes Gateway | latest | Running on Mac at `http://127.0.0.1:8642` |

### First-time Setup

```bash
# 1. Start the emulator
emulator -avd HermesPhone -no-snapshot -wipe-data

# 2. Verify Hermes Gateway is running on the Mac
curl http://127.0.0.1:8642/health
# → {"status":"ok","platform":"hermes-agent"}

# 3. Set up ADB reverse proxy (enables emulator → Mac communication)
adb reverse tcp:8642 tcp:8642

# 4. Run the app
cd ~/workspace/keryx
flutter run -d emulator-5554
```

### First Launch

1. App shows the **Setup screen** (only on first launch)
2. Enter Server URL: `http://10.0.2.2:8642`
3. API Key: leave blank (or provide if your Hermes Gateway has auth)
4. Tap **Connect**
5. On success → auto-navigates to **Chat screen**
6. Subsequent launches skip setup and go directly to Chat

## Architecture & Data Flow

### State Management

**Provider** (no external state management library — uses `provider` + `ChangeNotifier`):

```
MaterialApp
 └─ MultiProvider
     ├─ ConnectionProvider (ChangeNotifier)
     │   ├─ api: HermesApiService (HTTP client singleton)
     │   ├─ connected / connecting / error / capabilities
     │   └─ loadAndConnect() / connect() / disconnect()
     │
     └─ ChatProvider (ChangeNotifierProxyProvider<ConnectionProvider>)
         ├─ _sessions: List<ChatSession>    ← all conversations
         ├─ _currentIndex: int              ← active session
         ├─ _state: ChatState (idle|streaming|error)
         ├─ _currentResponse: String        ← live streaming text
         ├─ _currentRunId: String?          ← active Runs API session
         └─ _pendingFiles: List<FileOutput> ← files from Runs API
```

### Data Flow — Sending a Message

```
User taps Send
│
├─ ChatProvider.sendMessage(text)
│   ├─ Creates ChatMessage(role: 'user')
│   ├─ Appends to current session + saves to disk
│   ├─ Sets _state = streaming
│   │
│   ├─ If _useRunApi == false (Chat Completions mode) ──────────────────────┐
│   │   └─ _sendMessageChat(userMsg)                                        │
│   │       └─ hermesApiService.chatCompletionsStream(messages)             │
│   │           └─ SSE: data: {"delta": "..."}                              │
│   │                                                                       │
│   ├─ If _useRunApi == true (Runs API mode) ──────────────────────────────┐│
│   │   └─ _sendMessageRun(userMsg)                                        ││
│   │       ├─ startRun(messages) → run_id                                 ││
│   │       └─ runEventStream(run_id)                                      ││
│   │           ├─ event: message.delta   → delta text (streaming)         ││
│   │           ├─ event: reasoning.available → full text (fallback)       ││
│   │           ├─ event: tool_call       → "🔧 Using tool..." italic      ││
│   │           ├─ event: file            → FileOutput (url, name, mime)   ││
│   │           └─ event: run.completed   → break + final save             ││
│   │                                                                       ││
│   └─ Both paths: ─────────────────────────────────────────────────────────┘│
│       ├─ Appends ChatMessage(role: 'assistant', content, files)           │
│       ├─ Sets _state = idle                                               │
│       └─ _saveSessions() to JSON file                                     │
│                                                                           │
└─ Consumer<ChatProvider> detects changes via notifyListeners()
    └─ ChatScreen rebuilds ListView
```

### Route Flow

```
App Start
├─ SharedPreferences has 'keryx_base_url'?
│   ├─ YES → initialRoute: '/chat'
│   │         └─ ChatScreen (no back button → PopScope)
│   │
│   └─ NO  → initialRoute: '/setup'
│             └─ SetupScreen → connect() → pushReplacementNamed('/chat')
│                                                      └─ ChatScreen
│
Navigation:
  /chat      → /sessions (history list)
  /chat      → /settings
  /settings  → "Edit Connection" → dialog → reconnect
  /settings  → "Disconnect"      → pushReplacementNamed('/setup')
```

### Runs API vs Chat Completions

| Mode | API Endpoint | Features | Icon |
|------|-------------|----------|------|
| **Chat** (default) | `POST /v1/chat/completions` | Streaming text only | 💬 |
| **Run** (toggle in AppBar) | `POST /v1/runs` + SSE events | Tool calls, file outputs, reasoning | 🖥️ |

Toggle button in AppBar: `_useRunApi` boolean on `ChatProvider`.

## Key Components

### 1. HermesApiService (`lib/services/hermes_api_service.dart`)

The HTTP client. Handles all communication with Hermes Gateway.

**Key methods:**

| Method | Description |
|--------|-------------|
| `checkHealth()` | `GET /health` — returns bool |
| `getCapabilities()` | `GET /v1/models` — returns model details |
| `listModels()` | `GET /v1/models` — returns model list |
| `chatCompletionsStream(messages)` | SSE stream for `POST /v1/chat/completions` |
| `startRun(messages)` | `POST /v1/runs` — returns `run_id` |
| `runEventStream(runId)` | `GET /v1/runs/{id}/events` — SSE event stream |

**SSE Parser** (lines ~230-270):
- Splits lines by `\n`
- Tracks `_lastEvent` from `event:` lines
- Yields `{'event': String, 'data': String}` for each `data:` line
- Stops on `data: [DONE]` or when stream closes

### 2. ChatProvider (`lib/providers/chat_provider.dart`)

The brain of the app. Manages:

- `_sessions` — in-memory list of all conversations
- `_currentIndex` — which session is active
- `_state` — ChatState enum (idle / streaming / error)
- `_currentResponse` — live streaming text buffer
- `_useRunApi` — mode toggle
- `_currentRunId` — active Runs API session
- `_pendingFiles` — files received during a Run

**Key methods:**

| Method | Description |
|--------|-------------|
| `sendMessage(text)` | Entry point — creates user msg, dispatches to Chat/Runs API |
| `loadSessions()` | Loads from JSON file on app start |
| `_saveSessions()` | Persists to JSON file |
| `createNewSession()` | Creates empty session |
| `switchToSession(index)` | Switches active session |
| `deleteCurrentSession()` | Deletes + saves |
| `cancelStream()` | Stops streaming |
| `clearAllSessions()` | Deletes all data |
| `pickImageFromGallery/Camera()` | Image attachment flow |

**Persistence migration:**
- First version saved to internal storage (`getApplicationDocumentsDirectory` — `/data/data/.../app_flutter/`)
- This path gets wiped by `flutter run` reinstall
- Current version saves to external storage (`getExternalStorageDirectory` — `/storage/emulated/0/Android/data/com.keryx.keryx/files/`)
- `_migrateIfNeeded()` copies old data from internal → external on first run

### 3. ChatScreen (`lib/screens/chat_screen.dart`)

Largest file (~845 lines). Layout:

```
PopScope (canPop: false, prevents unintended back navigation)
└─ Scaffold
    ├─ AppBar (automaticallyImplyLeading: false)

    │       ├─ New Chat button (➕)
    │       ├─ Sessions button (📋)
```

## Persistence

### Session Data

| Aspect | Detail |
|--------|--------|
| **Location** | External: `/storage/emulated/0/Android/data/com.keryx.keryx/files/keryx_sessions.json` |
| **Format** | `List<ChatSession.toPersistJson()>` — full JSON serialization |
| **When saved** | After each user message, after each assistant response, on session create/delete |
| **When loaded** | On app start via `loadSessions()` called from `main.dart` provider `create` |
| **Migration** | `_migrateIfNeeded()` copies from old internal path on first run |

### Connection Config

| Aspect | Detail |
|--------|--------|
| **Storage** | `SharedPreferences` (Android: `/data/data/com.keryx.keryx/shared_prefs/`) |
| **Keys** | `keryx_base_url`, `keryx_api_key` |
| **When saved** | On successful `connect()` |
| **When loaded** | Via `ConnectionProvider.loadAndConnect()` (not currently called — config checked at app start in `main.dart`) |

### Image Attachments

Images are **not** persisted in sessions.json by default. The `imageDataUri` field is saved if present (base64 data URI), but large images can bloat the file. Currently images are stored inline in the JSON.

## Build & Run Details

### ADB Reverse Proxy

**Critical:** The emulator cannot reach `localhost:8642` on the Mac directly. You must run:
```bash
adb reverse tcp:8642 tcp:8642
```
This routes `http://10.0.2.2:8642` from the emulator to `localhost:8642` on the host.

**After emulator restart:** Must be re-run.

### Emulator

- **Name:** `HermesPhone`
- **Device:** Pixel 6 Pro (1080×2400, 420dpi)
- **System image:** `system-images;android-35;google_apis_playstore;arm64-v8a`
- **Start command:**
  ```bash
  emulator -avd HermesPhone -no-snapshot -wipe-data
  ```

### Flutter Run

```bash
cd ~/workspace/keryx
flutter run -d emulator-5554
```

**Note:** `flutter run` reinstalls the APK and clears internal app data. External storage (session JSON) survives the reinstall. SharedPreferences (connection config) does NOT survive — you'll see the Setup screen again.

## API Reference

Keryx communicates with Hermes Gateway's OpenAI-compatible REST API.

| Endpoint | Method | Used By | Notes |
|----------|--------|---------|-------|
| `/health` | GET | ConnectionProvider | Returns `{"status":"ok"}` |
| `/v1/chat/completions` | POST | Chat Completions | Standard SSE streaming |
| `/v1/runs` | POST | Runs API | Returns `run_id` |
| `/v1/runs/{id}/events` | GET | Runs API | SSE: message.delta, tool_call, file, run.completed |

### Runs API Event Format

Events are sent as `data: {json}` SSE lines. The JSON body contains an `event` field:

```json
data: {"event": "message.delta", "run_id": "...", "delta": "Hello..."}
data: {"event": "reasoning.available", "run_id": "...", "text": "Hello world"}
data: {"event": "tool_call", "run_id": "...", "tool": "web_search", "args": {...}}
data: {"event": "file", "run_id": "...", "url": "http://...", "mimeType": "image/png"}
data: {"event": "run.completed", "run_id": "...", "output": "Hello world", "usage": {...}}
```

The stream ends with `: stream closed` (SSE comment).

## Known Issues & Workarounds

### 1. SharedPreferences cleared on `flutter run`

**Issue:** `flutter run` clears app internal data, including SharedPreferences. After reinstall, the app shows Setup screen even if config was previously saved.

**Impact:** Low — user re-enters URL and connects. Sessions (on external storage) survive.

**Fix idea:** Save connection config to the same external storage path as sessions.

### 2. Runs API mode not persisted

**Issue:** The `_useRunApi` toggle resets when the app restarts (it's an in-memory boolean, not saved).

**Impact:** Low — user toggles back if needed.

**Fix idea:** Toggle state in SharedPreferences.

### 3. Image data URI in session JSON bloat

**Issue:** Base64-encoded images are saved inline in `sessions.json`. Large images make the file huge.

**Impact:** Sessions file can grow large with images.

**Fix idea:** Save images to a separate assets directory, store only the file path in JSON.

### 4. Connection loss between `flutter run` sessions

**Issue:** The `flutter run` process exits and loses its log output. The app keeps running on the emulator but you lose debug logging.

**Impact:** Low — normal behavior for Flutter debug builds.

**Workaround:** Use `flutter logs` to see app output after the fact, or run `flutter run` without background.

### 5. Adaptive icon warning about alpha channel

**Issue:** The source PNG has an alpha channel, which is flagged by Apple's App Store guidelines but doesn't affect Android.

**Impact:** None for Android. Ignore the warning.

## Extending Keryx

### Adding a New Screen

1. Create `lib/screens/my_screen.dart`
2. Add route in `lib/main.dart` `onGenerateRoute`
3. Navigate: `Navigator.pushNamed(context, '/my-screen')`

### Adding a New API Feature

1. Add method to `HermesApiService`
2. Wire it up in `ChatProvider`
3. Update UI in `ChatScreen`

### Adding User Preferences

Use `SharedPreferences` for simple key-value settings (like `_useRunApi` toggle, model selection, theme preference). See `ConnectionProvider` for the pattern.

### Adding External Storage Files

Use `_storageDir()` pattern from `ChatProvider`:
```dart
final dir = await _storageDir();
final file = File('${dir.path}/my_file.json');
```

### Modifying Data Models

Edit `lib/models/chat_message.dart`. Both `toJson()` and `toPersistJson()` (with `fromPersistJson()`) must be kept in sync.
